## Root Cause Analysis

Test #3 spectator path: laptop receives `AttackerDiceResult` → `DefenderDiceResult` →
enters `ShowBlitzDice` → gets killed before it finishes.

Five separate killers were identified and fixed, in order of discovery:

### Kill 1 — `currentSourceId`/`currentTargetId` were -1
Spectator never receives `SpawnDice`, so source/target were only set via `OnAttackSelection`.
Race condition: `AttackerDiceResult` could arrive before `AttackSelection` was processed,
leaving `-1` values. `ShowBlitzDice` called `PositionPanel(-1, -1)` → panel wrong position.

**Fix:** Added `sourceId`/`targetId` to `AttackerDiceResult` payload (server). Stored in
`OnAttackerDiceResult` on Unity side — authoritative regardless of event ordering.

### Kill 2 — `On<string>` wrong SignalR deserialisation
Changed `AttackerDiceResult` from `int[]` to object payload, used `connection.On<string>`
to receive it. SignalR sends JSON objects as `JsonElement`, not strings — handler never fired.
Silent failure; event appeared to work because no error was thrown.

**Fix:** Changed to `connection.On<JsonElement>` with manual property extraction, matching
the pattern used by `BlitzResult`, `SpawnDice`, and all other object payloads in the file.

### Kill 3 — `OnCombatResult` reset the arena
`CombatResult` arrived ~500ms after `DefenderDiceResult`. `ShowBlitzDice` is async —
hadn't set `state = ShowingBlitz` yet when `OnCombatResult` fired. Guard only checked
`ShowingBlitz`; missed the window between `DefenderDiceResult` arrival and first `await`.

**Fix:** Added guard in `OnCombatResult`: if `currentRole == None && lastAttackerValues.Length > 0`
→ spectator path is pending, don't reset.

### Kill 4 — `OnStateChanged` reset the arena (the main killer)
After `AttackWithDice` returns, server restores state (`TurnPhase = Reinforce`) and broadcasts
`GameStateUpdated`. `OnStateChanged` saw `turnPhase != "Attack"` and called `ResetCombat()`
immediately — killing `ShowBlitzDice` mid-sweep. In the test run this happened 9 times in
rapid succession (5s of repeated state updates from the test endpoint restore loop).

Confirmed via console logs: sweep started (`state=ShowingBlitz`), then immediately killed by
`OnStateChanged`.

**Fix:** Added `state != CombatState.ShowingBlitz` to the `OnStateChanged` reset condition.
`ShowBlitzDice` already calls `ResetCombat()` + `ZoomOut()` at its own end.

### Kill 5 — Duplicate `DefenderDiceResult` caused jank 2/3 through
`OnDefenderDiceResult` fired twice (duplicate enqueue in `UnityMainThread`). Second call
entered `ShowBlitzDice` while first was mid-sweep, called `diceRoller.ClearDice()` wiping
the placed dice, then restarted the flypath — causing visible jank and early termination.

Source of the double-fire not fully diagnosed (likely double `connection.On` registration
somewhere in `SignalRClient` — needs investigation next session).

**Fix:** Re-entry guards added:
- `OnDefenderDiceResult`: early return if `state == ShowingBlitz`
- `ShowBlitzDice`: early return if `state == ShowingBlitz` (belt-and-braces)

## Outstanding Issue — Double `DefenderDiceResult`

Console logs show `[SignalR] DefenderDiceResult` firing twice per combat on the spectator TV.
Both originate from `SignalRClient:<Start>b__59_17` at line 208, suggesting the
`connection.On<int[]>("DefenderDiceResult", ...)` handler is registered twice.

Possible causes:
- `Start()` on `SignalRClient` running twice (scene reload, object duplication)
- Connection rebuilt and handlers re-registered without clearing old ones (reconnect path?)
- Two `SignalRClient` instances in scene (only one found in hierarchy — but worth rechecking)

Re-entry guards added as mitigation. Root cause needs investigation.

## Key Lesson

`OnStateChanged` is a global kill switch — any state broadcast with `turnPhase != "Attack"`
will terminate any active arena display unless explicitly guarded. The blitz display
(`ShowingBlitz`) needs to be exempt from this, same as it's exempt from `OnCombatResult`.
Pattern: **every "kill arena" code path must check `state != ShowingBlitz`**.
