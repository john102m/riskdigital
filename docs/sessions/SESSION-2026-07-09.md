## Root Cause

The attacker TV's `OnSpawnDice("attacker")` spawned red dice with physics but deliberately
delayed reading/submitting them — waiting for `SpawnDice("defender")` to arrive before
starting `WaitSettleAttacker()`. Comment: "Don't settle yet — wait for SpawnDice("defender")
to know the household layout."

For a human defender, `SpawnDice("defender")` only arrives when they tap Roll (via `PlayerRoll`).
So the attacker dice physically settled on the attacker TV (looked fine there) but were never
read and submitted to the server until the defender tapped Roll.

Timeline before fix:
1. Attacker TV: red dice physically settle (look fine on screen) — **not submitted**
2. Defender TV: ghost red settle with **random physics faces** (no authoritative values yet)
3. Defender handset: RollPrompt arrives, human ponders (sees wrong red faces)
4. Human taps Roll → `SpawnDice("defender")` broadcast
5. Attacker TV: finally reads/submits → `AttackerDiceResult` broadcast
6. Defender TV: snaps red (too late — blue already rolling)

## Fix

**`EarlySettleAttacker`** — new async method on `CombatTheatre`. Starts immediately when
attacker dice spawn on the owning TV. Waits for physics settle, reads faces, submits to
server. Guards against role upgrade (SameHousehold) and double-submit.

This means `AttackerDiceResult` reaches the defender TV while the human is still pondering —
ghost red snap happens before blue dice ever spawn.
